## Per-Corpus Layout & `research-db/` Schema v2

```text
<tree>/<name>/README.md                   corpus index (doc table, outline scores, weight summary, preflight)
<tree>/<name>/<NN>-<slug>.md              authored docs in outline order (every claim cited with URL + Clef weight)
<tree>/<name>/research-db/preflight.json  searXNG + /api/decide preflight probe record
<tree>/<name>/research-db/outline.json    subtopics + Clef score validation (0=drop, 1=marginal, 2=load-bearing)
<tree>/<name>/research-db/archive.json    every collected searXNG result with non-null Clef noul weight
<tree>/<name>/research-db/digs/*.json     per-doc query attempts, redo logs, kept URLs, and outcome
<tree>/<name>/research-db/jev-log.json    every decision request with model, question names, and token usage
<tree>/<name>/research-db/db.ts           TypeScript interfaces matching all research-db JSON records
```

Every factual claim in a corpus doc carries its source URL and the Clef (`@cf/cloudflare/clef`) quality weight (`noul` probability in `[0, 1]`, or explicit ground-source attribution for internal-record subtopics). `research-db/` holds the complete collection and decision record so every corpus remains auditable.
