# 09 - Gap-Aware Ideation Opportunities

Scope: unexplored angles for differentiating an autonomous ideation skill: gap-awareness as an evaluation axis, skill-format portability inside an agent runtime, and structured kill verdicts as first-class outputs.

## Gap-awareness: the closest published work

The strongest anchor for gap-aware evaluation is "Mind the Blind Spots: A Focus-Level Evaluation Framework for LLM Reviews" (EMNLP 2025 main). It "introduces a focus-level evaluation framework for assessing LLM reviews, which computes focus distributions and compares them against human reviews based on predefined facets", and states "the focus-level evaluation offers actionable insights into how to improve LLMs' paper review capability and how to most effectively leverage LLM reviews in the peer review process" (source: https://aclanthology.org/2025.emnlp-main.1805/, weight 0.86). The arXiv version repeats the framing (source: https://arxiv.org/pdf/2502.17086v4, weight 0.74) and the HTML version confirms the actionable-insight claim (source: https://arxiv.org/html/2502.17086v4, weight 0.74).

The significance: focus-level evaluation measures what a review does NOT cover, facet by facet, against a human reference distribution. Applied to ideation, the same construction measures what a generated idea set systematically fails to cover. That is the gap-awareness axis the source doc identifies as unexplored: published ideation evaluation measures novelty and feasibility (doc 05, source: https://arxiv.org/pdf/2503.00946, weight 0.80), not coverage gaps.

The same experiment series also bounds what an autonomous loop can self-evaluate: "LLMs Cannot Evaluate Ideas Reliably" (source: https://arxiv.org/pdf/2409.04109, weight 0.75). A gap-map produced by the generating LLM itself is therefore suspect; the design implication is to make the gap-map a structured artifact that a separate critique pass or a human checks, not a free-text self-assessment.

## Skill-format portability

Portability as a distribution strategy has its own literature now. Microsoft's Agent Skills documentation defines the format: "portable packages of instructions, scripts, and resources that agents discover and load on demand" (source: https://learn.microsoft.com/en-us/agent-framework/agents/skills, weight 0.82). Microsoft Research's SkillOpt goes further, treating agent skills as trainable parameters: "AI agents often fail because their instructions, or skills, are manually modified with no guarantee of improvement. Learn how SkillOpt turns skill editing into a training process, making agent behavior more reliable without changing" the model (source: https://www.microsoft.com/en-us/research/blog/skillopt-agent-skills-as-trainable-parameters/, weight 0.87).

Community practice confirms the portability pattern in the ideation niche specifically. The ideate-skill repository advertises itself as an "Agent Skill for Claude and OpenAI" and notes that pointing any agent at ideate/SKILL.md works because "it's just instructions"; the .skill file is the ideate folder zipped, so one unzip drops it into either skills home (source: https://github.com/nelsonwerd/ideate-skill, weight 0.47, weak backing). A portable-agent-skills reference guide covers "when the skill must load across Agent Skills-compatible clients rather than depend on Claude Code extensions" (source: https://github.com/conorbronsdon/agent-skill-builder/blob/main/references/portable-agent-skills.md, weight 0.35, weak backing). This is the exact contrast with doc 03: pipeline products require a deployment; a SKILL.md inherits the host agent's memory, tools, and session state.

## Structured kill verdicts

The kill-verdict pattern appears in the skill ecosystem in primitive form. A "verdict" skill frames adversarial review so that "a verdict of STANDS earned under real fire is worth more than a thousand compliments", with the prime rule that "every strike must be the strongest real attack available, and every miss must be recorded as a miss" (source: https://github.com/andrewcovenant/skills/blob/main/skills/verdict/SKILL.md, weight 0.33, weak backing). The source doc's proposal, structured KILL/PAUSE/REVISE/SHIP verdicts with explicit reasoning as a sibling output of ideation, generalizes this into a decision taxonomy. No ideation system in this corpus (docs 01 through 05) publishes such a taxonomy; the strongest systems publish loop verbs and scoring dimensions instead.

## The open opportunity, stated

Combining the three threads: published ideation evaluation lacks a coverage-gap axis (doc 05; source: https://arxiv.org/pdf/2503.00946, weight 0.80), the closest mechanism exists in adjacent evaluation work on reviews (source: https://aclanthology.org/2025.emnlp-main.1805/, weight 0.86), self-evaluation is known unreliable (source: https://arxiv.org/pdf/2409.04109, weight 0.75), and the skill format is a standardized portable substrate (source: https://learn.microsoft.com/en-us/agent-framework/agents/skills, weight 0.82). The differentiation path for an autonomous ideation skill is therefore: emit a structured gap-map alongside each idea, gate continuation on it, produce a KILL/PAUSE/REVISE/SHIP verdict per idea, and ship the whole thing as a portable SKILL.md rather than a deployed pipeline.
