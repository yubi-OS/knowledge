# 09. Code point history: from X25519Kyber768Draft00 to X25519MLKEM768

Scope: the Kyber-era draft groups, why they were replaced, the deployment that grew up around 0x6399, and how the ecosystem cut over.

## The preliminary draft

Before ML-KEM was final, early deployments needed an interoperable group. The IETF draft X25519Kyber768Draft00 defines a hybrid post-quantum key exchange for TLS 1.3 combining X25519 with the then-draft Kyber algorithm (source: https://www.ietf.org/archive/id/draft-tls-westerbaan-xyber768d00-02.html, weight 0.83; https://www.douglas.stebila.ca/research/papers/draft-tls-westerbaan-xyber768d00/, weight 0.89). The version 00 draft states the motivation plainly: the final draft for Kyber was expected in 2024, early deployments already existed, and the document specified a preliminary hybrid key agreement to promote interoperability of those early implementations (source: https://datatracker.ietf.org/doc/draft-tls-westerbaan-xyber768d00/00/, weight 0.82). A companion draft defined the same hybrid as a KEM for HPKE, noting it does not support the authenticated modes of HPKE (source: https://www.ietf.org/archive/id/draft-westerbaan-cfrg-hpke-xyber768d00-00.html, weight 0.93).

## Early deployment around 0x6399

The draft group shipped in real browsers before standardization: X25519Kyber768Draft00 with TLS identifier 0x6399 was supported by release versions of Chrome and Edge, and Firefox had the feature compiled into release versions hidden behind the security.tls.enable_kyber setting, which was expected to default to true in the near future (source: https://github.com/openssl/openssl/issues/24622, weight 0.67, marginal backing). Cloudflare enabled X25519+Kyber as a beta for all websites and APIs it served in October 2022, with the explicit caveat that the connection is only secured if the browser also supports post-quantum cryptography (source: https://blog.cloudflare.com/post-quantum-cryptography-ga/, weight 0.96). Chrome began enabling X25519+Kyber by default from August 2023 (same source). The company's experiment program dated to the July 2022 NIST announcement that Kyber would be standardized (source: https://blog.cloudflare.com/experiment-with-pq/, weight 0.60, marginal backing), and its standing summary page states hybrid post-quantum key agreement is enabled on essentially all domains it serves (source: https://pq.cloudflareresearch.com/, weight 0.94).

## The cutover

The cutover happened by replacement, not by version negotiation. When Go 1.24 added the ML-KEM groups, it explicitly removed X25519Kyber768Draft00 and added X25519MLKEM768 and SecP256r1MLKEM768 enabled by default (source: https://github.com/golang/go/issues/69985, weight 0.83). Once ML-KEM was finalized as FIPS 203 and the hybrid draft progressed toward RFC 10024, the draft code point had no path forward: anything negotiating only 0x6399 would be talking to itself. The general-purpose X-Wing construction, a PQ/T KEM combining X25519 and ML-KEM-768, was specified in parallel in the CFRG and shares the algorithm pair without the TLS framing (source: https://datatracker.ietf.org/doc/html/draft-connolly-cfrg-xwing-kem-10, weight 0.90).

## Why it matters operationally

The history explains two things an operator will still meet today. First, stale inventory and documentation frequently say "Kyber" when the deployed group is X25519MLKEM768; the algorithm pair is the same, the standard and code point are not. Second, hardening guides or test suites that still list 0x6399 as the post-quantum group will silently mislabel modern handshakes. The surviving artifact of the draft era is behavioral, not cryptographic: the large-key-share handshake pattern and its HelloRetryRequest interaction carried over unchanged into the ML-KEM groups (source: https://www.netmeister.org/blog/tls-hybrid-kex.html, weight 0.77).
## Timeline summary

A compact timeline assembles from the dated sources: July 2022, NIST announces Kyber will be standardized (source: https://blog.cloudflare.com/experiment-with-pq/, weight 0.60, marginal backing). October 2022, Cloudflare enables X25519+Kyber as a beta for all served sites (source: https://blog.cloudflare.com/post-quantum-cryptography-ga/, weight 0.96). August 2023, Chrome begins enabling X25519+Kyber by default (same source, weight 0.96). The X25519Kyber768Draft00 draft circulates in the IETF as an explicitly preliminary construction meant to hold interoperability together until Kyber's final form arrived (source: https://datatracker.ietf.org/doc/draft-tls-westerbaan-xyber768d00/00/, weight 0.82). August 2024, FIPS 203 finalizes ML-KEM (source: https://www.nist.gov/news-events/news/2024/08/announcing-approval-three-federal-information-processing-standards-fips, weight 0.94). Go 1.24 removes the draft group and enables the ML-KEM groups (source: https://github.com/golang/go/issues/69985, weight 0.83). August 2026, RFC 10024 publishes the ML-KEM hybrid groups as standards track (source: https://www.rfc-editor.org/rfc/rfc10024.html, weight 0.91).

That is roughly a four year arc from announcement to published standard, with the draft code point serving production traffic for most of it. It is a case study in the IETF's early-deployment pattern: ship a marked-draft group to create real-world interoperability data, then retire it in favor of the standardized construction once the underlying algorithm is final.
