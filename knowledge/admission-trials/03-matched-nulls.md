# 03. Matched nulls: curveball and column-permutation null generation

Scope: matched nulls: curveball and column-permutation null generation, the second independent null seed, non-degenerate nulls, and why the null must match the observed data structure.

Program-specific statements derive from the instrument's trial record of 2026-09-19 (yubiOS refs/admission-trials-2026-09-19.md). External claims are cited inline with jev weight; weights below 0.5 are labeled weak backing.

## Why the null must match the data

A null model in network science is a baseline against which observed structure is compared: the question is whether a property of the observed network is unusual relative to what a matched random structure would produce (Testing against the null hypothesis: permutations and randomizations, Shizuka lab network analysis course notes, weight 0.787). In a permutation test, the null distribution is generated by shuffling the association between variables, and the p-value comes from comparing the observed statistic against that distribution (Applied Biostatistics, bookdown, weight 0.785). If the shuffle destroys properties of the data that the statistic depends on, the comparison is meaningless: the test measures the wrong thing.

Null-model-based data augmentation work states the role directly: in network science the null model is used to generate a series of graphs by randomization as a term of comparison to verify whether an observed pattern is special (arXiv 2112.00476, weight 0.771). The design of the null therefore determines what the comparison can detect.

## Curveball: fast degree-preserving randomization

The curveball algorithm is the framework's null generator for binary matrices. Its defining property is that it randomizes binary matrices (and bipartite networks) with fixed node degrees, exchanging ingroup sets between randomly chosen pairs of rows, which preserves row and column sums while mixing faster than switching-based alternatives (A unifying framework for fast randomization of ecological networks with fixed node degrees, PMC6072652, weight 0.919). The same authors explain the speed with a card-trade intuition: both curveball and the switching algorithm can be understood as games in which kids trade cards, and curveball trades whole hands at once, which mixes faster (Methods in Ecology and Evolution via ScienceDirect, weight 0.839).

Curveball is not the only option, and the choice matters. For weighted bipartite networks, recent work designs null models that preserve exact degree sequences while remaining unbiased, treating the preservation of structural properties as the fundamental design problem of null models (Physical Review E research letter, link.aps.org, weight 0.742). And a 2026 preprint on projected two-mode networks shows how null-model constraints affect statistical validation, contrasting the microcanonical curveball model with canonical bipartite configuration models (arXiv 2607.29242, weight 0.670). The lesson for any audit program: the null's constraint set is a design decision that determines which structures the test can call unusual.

## Column permutation and its limits

The second null family is label shuffling: permuting columns (or labels) to generate a null while keeping the row structure intact. This is the textbook permutation approach (Applied Biostatistics, bookdown, weight 0.785) and is the natural null for a trial that asks whether a per-axis verdict survives when the axis assignments are randomized. Its limits are inherited from what it preserves: a column permutation preserves the column's content wholesale, so any structure that lives inside a column is carried into the null and can never be detected as unusual. General-purpose permutation-test tutorials note the same trade-off: the statistic's probability under the null is obtained by re-randomizing labels, so only the statistic's dependence on the labeling is being tested (GeeksforGeeks, permutation tests in machine learning, weight 0.120, weak backing).

## Two independent seeds and non-degenerate nulls

The trial framework requires a second independent null seed, and requires that the nulls be non-degenerate. Both requirements are about Monte Carlo hygiene. Monte Carlo methods obtain results by repeated random sampling, so each run's draws are a sample from the null, not the null itself (Wikipedia, Monte Carlo method, weight 0.763). With 40 draws (K=40 in the trial's parameters), the null tails are estimated from a small sample, and a second independent seed checks whether the trial's verdicts depend on which 40 draws were taken. A degenerate null, one where every draw collapses to the same value or to a trivial case, would make the tails meaningless; the `null_nondegenerate` criterion guards this directly, per statistic.

## What the nulls are matched to

The trials' nulls are margin-matched random bit matrices: the curveball-style generation preserves the row and column margins of the observed matrix, so the comparison asks whether the observed statistic exceeds what margin-preserving randomization produces. This is the strongest form of matching and also the source of the margin traps covered in doc 04: the better the null matches the data's structure, the more conservative the test becomes.
