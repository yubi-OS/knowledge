# 08 - release ladder and maintenance state

Scope: current upstream maintenance state: the release version ladder across osbuild, osbuild-composer, image-builder, cockpit-image-builder, and the archived repos, plus RHEL errata.

## The version ladder

The project publishes a releases overview page listing the currently released versions with links to each changelog; the page is autogenerated by a bot and its snapshot records a last update of 2026-08-25 (https://osbuild.org/docs/on-premises/overview/release-overview/, noul 0.93). The ladder as verified 2026-09-29 in the yubiOS refs source research against that page: osbuild 53.1, osbuild-composer v191, cockpit-image-builder v179, image-builder v110, and bootc-image-builder v69 (https://osbuild.org/docs/on-premises/overview/release-overview/, noul 0.93). Forward motion lives in the unified image-builder at v110; the absorbed bootc-image-builder is frozen at v69.

The unified image-builder's releases page is active (https://github.com/osbuild/image-builder/releases, noul 0.94), while the image-builder-cli release list tops out at release 69, authored with reviewers noted in the changelog entry for the many: copy boot files from build change (https://github.com/osbuild/image-builder-cli/releases, noul 0.72).

## Archived repositories

The image-builder-cli repository is archived: the repository notice records the archive date as 2026-09-01 (https://github.com/osbuild/image-builder-cli, weak backing, noul 0.49, primary repository page but thin index text). Its final release, v69 dated 2026-06-17, is confirmed as the last one by the releases feed in the yubiOS refs verification (https://github.com/osbuild/image-builder-cli/releases, noul 0.72). This makes any fork of image-builder-cli a fork of a frozen upstream; the yubi-OS/image-builder-cli fork is in exactly that position, and new capability should be tracked against unified image-builder releases and the osbuild.org bootc migration page instead.

## The Cockpit frontend is still maintained

The Cockpit frontend for osbuild is under active security maintenance. Red Hat shipped cockpit-image-builder errata RHSA-2026:24331 for RHEL 10: the advisory describes image-builder-frontend as generating custom images suitable for deploying systems or uploading to the cloud, integrating into Cockpit as a frontend for osbuild, and rates the update Important (https://access.redhat.com/errata/RHSA-2026:24331, noul 0.81). Rocky Linux mirrored the same errata as RLSA-2026:24331, credited to the Red Hat advisory under CC-BY-4.0 (https://errata.rockylinux.org/RLSA-2026:24331, noul 0.88). A later advisory, RHSA-2026:71543, dated 2026-09-24, continued the sequence for the same component (https://access.redhat.com/errata/RHSA-2026:71543, noul 0.63). Cockpit itself positions its model as intentionally using system APIs and commands so a whole team of admins can manage a system (https://cockpit-project.org/, noul 0.67).

Third-party scanners track the same advisory, for example the Tenable plugin page for RHSA-2026:24331 (https://www.tenable.com/plugins/nessus/319645, weak backing, noul 0.30, an aggregator mirror of the Red Hat advisory).

## What the maintenance pattern says

Three facts define the current upstream state:

1. The engine and unified frontend are alive: image-builder v110 sits at the top of the ladder with an active releases page (https://github.com/osbuild/image-builder/releases, noul 0.94; https://osbuild.org/docs/on-premises/overview/release-overview/, noul 0.93).
2. The stateless CLI line is frozen: image-builder-cli is archived as of 2026-09-01 with v69 as its final release (https://github.com/osbuild/image-builder-cli, weak backing, noul 0.49).
3. The RHEL-delivered frontend is under security errata, not feature development: two 2026 advisories for cockpit-image-builder (https://access.redhat.com/errata/RHSA-2026:24331, noul 0.81; https://access.redhat.com/errata/RHSA-2026:71543, noul 0.63).

## yubiOS framing

For yubiOS the actionable read is the fork strategy: the fork of a frozen CLI is acceptable short term (v69 is stable and the --bootc-* entry points match the unified tool's compatibility surface), but the capability drift runs one way, and the composefs-native blocker chain (doc 07) progresses only in the unified line. The release overview page being bot-generated is also worth noting: it is a fresh-checkable source, so fork drift checks can poll one URL instead of scraping multiple repos.
