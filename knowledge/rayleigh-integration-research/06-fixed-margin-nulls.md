# 06 - Fixed-margin nulls for binary matrices: the checkerboard machinery

**Scope:** fixed-margin checkerboard and permutation nulls for binary matrices, certified margins, and exclusion-only verdicts at resolution 1/(K+1).

## The null model family

A fixed-margin null for a binary matrix samples matrices that preserve the observed row and column sums (the margins) while re-randomizing everything else. The Foundations of Data Science 2020 paper "Non-Uniform Sampling of Fixed Margin Binary Matrices" describes the canonical mechanism: start with the observed matrix and repeatedly swap 1s such that the constraints, the margins, are maintained (weight 0.89, [ACM FODS 2020](https://dl.acm.org/doi/epdf/10.1145/3412815.3416887); same paper on arXiv, weight 0.86, [arXiv:2007.15043](https://arxiv.org/pdf/2007.15043)). The paper's software release implements weighted versions of two named algorithms, checkerboard swapping and the curveball algorithm, to sample from fixed-margin distributions (weight 0.42, weak backing, [github.com/fouticus/nsfbm](https://github.com/fouticus/nsfbm)).

The reason fixed margins matter is control. A null that preserves row and column sums randomizes the arrangement of entries while holding the marginal structure constant, so any statistic that differs between the observed matrix and the null draws is attributable to structure beyond the margins. The FODS paper goes further and shows the choice of null model itself changes conclusions, illustrating the potential impact of a non-uniform null model on a classic bird habitation dataset (weight 0.89, [ACM FODS 2020](https://dl.acm.org/doi/epdf/10.1145/3412815.3416887)). For an instrument that compares observed graph statistics against null draws, that is the load-bearing caveat: the null is a hypothesis about what counts as unstructured, and margin-preservation is the narrowest such hypothesis.

Newer work continues on the same problem: a 2026 arXiv preprint presents a rejection-free MCMC sampler for binary matrices with fixed marginals, with keywords binary matrix, fixed margins, Markov chain Monte Carlo, contingency table, degree sequence (weight 0.26, weak backing, [arXiv:2608.17531](https://arxiv.org/html/2608.17531)).

## From null draws to verdicts: the permutation-test discipline

The inference machinery around the null draws is the standard permutation-test discipline. A permutation test evaluates a null hypothesis by comparing the observed test statistic to its distribution under random permutations, making no distributional assumption about the data beyond the exchangeable structure being permuted (weight 0.63, [cttir tutorials](https://cttir.github.io/tutorials/tutorials/inference/permutation-tests.html)). Springer's "Permutation Methods" chapter gives the systematic treatment of exact and Monte Carlo permutation statistical methods (weight 0.83, [Springer](https://link.springer.com/chapter/10.1007/978-3-032-08924-3_2)). Teaching material for constrained ordination describes the shape concretely: compute the test statistic for the real, unpermuted data first, then compute it again for each permuted replicate (weight 0.65, [davidzeleny.net](https://www.davidzeleny.net/anadat-r/doku.php/en:monte_carlo)).

Statistical software documents the resolution question directly: the permute command estimates p-values for permutation tests on the basis of Monte Carlo simulations (weight 0.49, weak backing, [Stata manual](https://www.stata.com/manuals13/rpermute.pdf)). With K null draws, the finest p-value resolution is 1/(K+1), because the observed statistic joins the K null statistics in the ranking. This is the arithmetic behind the instrument's exclusion-only verdicts: at K = 40, nothing below 1/41 can be resolved, so a value that is merely small relative to the null cannot be certified as extreme. The instrument therefore reports exclusion (outside the plus-or-minus two-sided tail) or no verdict, never a graded p-value it cannot support.

## Margins must be certified, not assumed

The instrument's implementation detail with the strongest correctness consequence is that margins are certified per draw, not merely targeted. The FODS paper's swap mechanism maintains margins exactly by construction (weight 0.89, [ACM FODS 2020](https://dl.acm.org/doi/epdf/10.1145/3412815.3416887)), and the instrument mirrors this by re-checking margins on every draw and rejecting any draw whose margins fail. A null whose margins silently drift would corrupt every downstream tail computation, so the certification is a runtime check, not an assumption.

The remaining caveats carry over from the shared V2 null machinery: K = 40 resolves nothing below 1/41, and finite mixing of the swap chain is not established. Both are recorded as honesty-boundary items rather than fixed: the null randomizes bit margins, not content, so it speaks to arrangement-level surprise, never to semantic content.
