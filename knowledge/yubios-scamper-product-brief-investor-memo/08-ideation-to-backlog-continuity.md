# 08. Ideation to backlog continuity

Scope: Turning ideation artifacts into durable backlog items: the graduation path from idea to product backlog, ticket filing as the first next step, and linking ideas to existing implementation capability.

## Why ideation output evaporates

Ideation artifacts die in three ways: the thread that produced them is lost, the outputs are never triaged into an actionable structure, or they are filed as raw ideas that no one re-evaluates. The idea-backlog pattern addresses this directly: an idea backlog is the starting point of a healthy product development process, and items graduate from the idea backlog to the product backlog only after they have been evaluated, refined into clear requirements, and prioritized for development (https://www.projectstrategizer.com/blog/idea-backlog, jev weight 0.19, weak backing).

That graduation gate is the discipline most ideation workflows skip. Raw SCAMPER output ("combine access control with a transparency dashboard") is not a backlog item; it becomes one when it is written as an evaluable requirement with a scope, an owner, and a link to the capability that would implement it.

## The two-tier structure

Agile practice already encodes the container for the second tier. The product backlog is the single source of truth for everything a team might build, ordered by what matters most, with defined item types, prioritization frameworks, and refinement cadence (https://bacentric.com/product-backlog/, jev weight 0.40, weak backing). A well-prioritized backlog makes release and iteration planning easier and broadcasts the team's intended work to stakeholders, including internal work the customer will never notice (https://www.atlassian.com/agile/scrum/backlogs, jev weight 0.61, authoritative). Backlog management falls to the product manager, whose key responsibility is to create, prioritize, and maintain it (https://www.toptal.com/product-managers/agile/product-backlog-step-by-step-guide, jev weight 0.23, weak backing).

Idea-management tooling formalizes the first tier: flexible workflow tools progress each idea through ideation stages and sync with development tools so progress is visible from one place (https://www.prodpad.com/features/ideas/, jev weight 0.22, weak backing). Step-by-step backlog-definition guides describe the same handoff in process terms (https://ones.com/blog/how-to-define-product-backlog-step-by-step-guide/, jev weight 0.31, weak backing). The commercial idea-management platform market is large and crowded (https://worldmetrics.org/best/idea-management-software/, jev weight 0.17, weak backing; https://inspireip.com/idea-and-innovation-management-software/, jev weight 0.10, weak backing; https://www.techjockey.com/us/blog/best-idea-management-software, jev weight 0.14, weak backing; https://innovationcast.com/blog/innovation-management-software, jev weight 0.22, weak backing; http://hypeinnovation.com/, jev weight 0.30, weak backing), which is a signal that the problem is common enough to sustain vendors, not evidence that any particular tooling is needed. For a small team, a ticket per idea is sufficient machinery.

## The filing procedure

For an ideation artifact containing a ranked shortlist, the minimal durable procedure:

1. File each strong suggestion as its own ticket, or extend an existing roadmap ticket when one already covers the same capability. The goal is that the idea survives in a system with review cadence, not in a document that gets read once.
2. Link each ticket to the existing implementation capability that would build it (in a skills-and-infrastructure context: the named skill or component that covers the substrate), so the ticket carries its own feasibility pointer.
3. Record the provenance in the ticket: which artifact, which section, and that it originated as ideation output pending validation.
4. Leave the ideation artifact in place as the historical record; the tickets reference it, the artifact does not become the tracker.

The broadcast function of the backlog matters for ideation specifically: once ideas are in the backlog, they broadcast intent to stakeholders, which converts private speculation into visible commitments that can be challenged (https://www.atlassian.com/agile/scrum/backlogs, jev weight 0.61, authoritative).
