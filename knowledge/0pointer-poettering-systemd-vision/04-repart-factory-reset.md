# 04 systemd-repart, First-Boot Partitioning, and Factory Reset

Scope: systemd-repart as the declarative partitioning engine of the vision: incremental GPT management, adaptive first-boot partition creation, factory reset semantics, and the no-installer goal.

## Incremental declarative partitioning

systemd-repart implements declarative, incremental partition management for GPT partition tables: it reads partition definitions from configuration files in repart.d/ directories and applies them (source: https://deepwiki.com/systemd/systemd/4.2-partition-management-with-systemd-repart, jev 0.22, low weight, secondary source). The upstream man page is precise about the operation model: repart operations are mostly incremental, it grows existing partitions or adds new ones, but does not shrink, delete, or move existing partitions, and the service is intended to be run on every boot (source: https://www.freedesktop.org/software/systemd/man/latest/systemd-repart.html, jev 0.91). The declarative state model means the administrator defines the desired end state of the partition table rather than issuing raw sector manipulation commands (source: https://digitash.com/linux/linux-configure-systemd-repart-declarative-gpt-partition-table-provisioning/, jev 0.32, low weight).

## First-boot adaptive partitioning

Because repart is idempotent and runs on every boot, the same image can be flashed to a small SBC or a large server: on first boot repart creates missing partitions and grows the root to fill the disk (source: https://www.freedesktop.org/software/systemd/man/latest/systemd-repart.html, jev 0.91). This implements the vision's adaptive goal: systemd-repart creates the root filesystem on first boot, encrypts it, and enrolls a TPM2 key in that same pass (source: https://0pointer.net/blog/fitting-everything-together.html, jev 0.95). The essay's no-installer goal depends on this: any image is a live image, installation is dd to disk, and first-boot repart finishes the job (source: https://0pointer.net/blog/fitting-everything-together.html, jev 0.95).

## Factory reset

The FactoryReset= marker is the core mechanism: repart partitions flagged FactoryReset=yes are the ones a reset wipes. The man page documents that setting the factory-reset switch to true removes all existing partitions marked with FactoryReset= set to yes early while executing the re-partitioning algorithm, and to use it with care (source: https://www.freedesktop.org/software/systemd/man/systemd-repart.html, jev 0.84). The systemd.io design document explains the scope: a factory reset implemented with systemd's tools can reset or erase partitions via systemd-repart and reset the TPM (source: https://systemd.io/FACTORY_RESET/, jev 0.65). v259 added --defer-partitions-factory-reset= to repart, letting a deployment delay the reset of specific partition types (source: https://github.com/systemd/systemd/releases, jev 0.77, per the parent source material).

## Configuration surface

repart definition files use standard systemd INI syntax and are processed in alphabetical order; a common pattern is a definition that auto-expands the root partition to the full disk (source: https://digitash.com/linux/linux-configure-systemd-repart-declarative-gpt-partition-table-provisioning/, jev 0.32, low weight). mkosi integrates directly: RepartDirectories= and --repart-directory= point at directories containing systemd-repart partition definition files that mkosi uses when invoking systemd-repart to build a disk image (source: https://github.com/systemd/mkosi/blob/main/mkosi/resources/man/mkosi.1.md, jev 0.87). This is the pipeline the vision prescribes: mkosi builds the image with repart definitions, and the same definitions drive first-boot growth on the target machine.

## Recent capability growth

Repart features land steadily in the v256 to v261 window: v258 added fsverity support in systemd-repart, and the v259 release exposed a Varlink IPC API for repart (source: https://github.com/systemd/systemd/blob/main/NEWS, jev 0.87, and https://github.com/systemd/systemd/releases, jev 0.77, per the parent source material). v261 added EncryptKDF=, VolumeName=, BlockDeviceReplace=, --grain-size=, and per-partition Discard= options, strengthening the install, migration, and encrypted-partition flow (source: https://github.com/systemd/systemd/releases/tag/v261, jev 0.86, per the parent source material). v261 also introduced systemd-sysinstall, a textual installer wrapping systemd-repart plus bootctl, the closest upstream counter-trend to the no-installer goal: it exists, but it is built on repart rather than replacing it (source: https://github.com/systemd/systemd/releases/tag/v261, jev 0.86, and https://lwn.net/Articles/1078708/, jev 0.66, per the parent source material).
