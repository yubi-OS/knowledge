# Supply Chain Gates

yubiOS hardens its supply chain with four layers, each catching what the previous one cannot. Layer 1 pins every build input by content address. Layer 2 vets every input with an OPA/Rego policy before any layer executes. Layer 3 makes the build deterministic and proves it with a two-build byte comparison. Layer 4 attaches cosign signatures plus SLSA v1.0 provenance and SPDX SBOM attestations to every published artifact, with a SLSA Build L3 target and a Rekor v2 transparency-log posture defined in a dated integration spec. Sources: [yubiOS.rego](https://raw.githubusercontent.com/yubi-OS/yubiOS/main/yubiOS.rego), [docs/ADR.md](https://raw.githubusercontent.com/yubi-OS/yubiOS/main/docs/ADR.md), [refs/reproducible-builds-2026-07-22.md](https://raw.githubusercontent.com/yubi-OS/yubiOS/main/refs/reproducible-builds-2026-07-22.md), [refs/slsa-l3-sbom-cosign-integration-spec-2026-08-04.md](https://raw.githubusercontent.com/yubi-OS/yubiOS/main/refs/slsa-l3-sbom-cosign-integration-spec-2026-08-04.md).

## Layer 1: Digest-pinned inputs

The base image is `quay.io/fedora/fedora-bootc:45`, pinned by SHA256 digest under ADR-015; mutable tags (`:latest`, `:45` without a digest suffix) are forbidden because a digest is content-addressed and immutable. The live digest lives in [PINNED.md](https://raw.githubusercontent.com/yubi-OS/yubiOS/main/PINNED.md), the declared single source of truth (fedora-bootc digest re-resolved 2026-08-05; version-sensitive). ADR-015's bump policy requires every new digest to still ship the required floors, including the systemd target, pam-u2f >= 1.3.1, and OpenSSL 3.5+, and its amendments (2026-07-07 and 2026-07-11) warn that digests embedded in ADR text are historical evidence, never current pins. Sources: [docs/ADR.md](https://raw.githubusercontent.com/yubi-OS/yubiOS/main/docs/ADR.md) (ADR-015), [PINNED.md](https://raw.githubusercontent.com/yubi-OS/yubiOS/main/PINNED.md).

Pinning does not stop at the base image. ADR-030 requires GitHub Actions pinned to full commit SHAs, container bases to OCI digests, source checkouts to immutable commit refs, and downloaded tools to a reviewed version plus checksum; a workflow must fail rather than silently fall back to a moving tag, unsigned download, or unverified alternate source. [PINNED.md](https://raw.githubusercontent.com/yubi-OS/yubiOS/main/PINNED.md) operationalizes this: every `wcurl` payload (Docker CLI 29.6.0, Buildx v0.35.0, cosign v3.1.2) is SHA-512 verified with `--check --strict`, and yubi-OS forks of TF-A, EDK2, mkosi, OP-TEE, ms-tpm-20-ref, and U-Boot consume immutable source commits, not mutable release tags. Sources: [docs/ADR.md](https://raw.githubusercontent.com/yubi-OS/yubiOS/main/docs/ADR.md) (ADR-030, item 6), [PINNED.md](https://raw.githubusercontent.com/yubi-OS/yubiOS/main/PINNED.md).

## Layer 2: Docker Build Policies (yubiOS.rego)

[yubiOS.rego](https://raw.githubusercontent.com/yubi-OS/yubiOS/main/yubiOS.rego) is the OPA/Rego policy evaluated by Docker Buildx's Build Policies feature (`docker buildx build --policy reset=true,strict=true,filename=yubiOS.rego`; Docker documents Rego as its policy language, with OPA as the engine, source: [docs.docker.com/build/policies](https://docs.docker.com/build/policies/)). It is default-deny (`default allow := false`) and vets every build input before any layer executes, so violations fail the build before anything is pulled. Source: [yubiOS.rego](https://raw.githubusercontent.com/yubi-OS/yubiOS/main/yubiOS.rego).

The policy enforces: Rule 1 passes pure local builds with no `FROM` pull. Rule 2 requires every external image reference to come from an approved registry AND be canonical (`input.image.isCanonical`), rejecting mutable tags with a remediation message naming the `FROM ...@sha256:<hash>` form. Approved registries: `quay.io/fedora/`, `dhi.io/`, `ghcr.io/actions/`, `ghcr.io/hadolint/`; `docker.io/docker/*` is deliberately not blanket-approved. Rule 2.5 grants one narrow carve-out, `docker.io/docker/buildkit-syft-scanner:stable-1`, pulled internally by BuildKit during the SBOM attestation pass and never landing in a runtime image; any future BuildKit-internal helper needs its own explicit exception. Rule 3 (`input.image.hasProvenance`) exists but stays commented out until `quay.io/fedora/fedora-bootc` ships provenance. Source: [yubiOS.rego](https://raw.githubusercontent.com/yubi-OS/yubiOS/main/yubiOS.rego).

The runtime choice is deliberate: ADR-014 selects rootless Docker Buildx as the sole container build runtime and removes Podman, because Build Policies are a Buildx feature with no Buildah equivalent and one runtime means one audit target; Buildx also emits provenance and SBOM attestations natively via `--attest`. Source: [docs/ADR.md](https://raw.githubusercontent.com/yubi-OS/yubiOS/main/docs/ADR.md) (ADR-014).

## Layer 3: Reproducible builds

ADR-030 fixes the build environment as one indivisible pattern: a digest-pinned Docker Hardened Image job container as the privileged outer boundary, checksum-pinned Docker CLI plus rootless dockerd on an unprivileged user's socket, an explicitly selected Buildx builder named `hardened` whose BuildKit daemon image (`docker.io/moby/buildkit:v0.31.2`) is pinned independently of the client, and [yubiOS-bake.hcl](https://raw.githubusercontent.com/yubi-OS/yubiOS/main/yubiOS-bake.hcl) as the only invocation path. Every Bake target must inherit `_policy` and `_reproducible`, declare its attestation boundary, and carry a policy-negative test. Sources: [docs/ADR.md](https://raw.githubusercontent.com/yubi-OS/yubiOS/main/docs/ADR.md) (ADR-030), [PINNED.md](https://raw.githubusercontent.com/yubi-OS/yubiOS/main/PINNED.md).

Pinning alone is not proof of reproducibility, and ADR-030 says so. [refs/reproducible-builds-2026-07-22.md](https://raw.githubusercontent.com/yubi-OS/yubiOS/main/refs/reproducible-builds-2026-07-22.md) makes it executable: the canonical build identity is the commit plus its committer timestamp, derived once by `scripts/lib/reproducible-build.sh` so a caller cannot silently assign a different `SOURCE_DATE_EPOCH` to the same revision (spec: [reproducible-builds.org](https://reproducible-builds.org/specs/source-date-epoch/)). Bake passes `SOURCE_DATE_EPOCH` and `BUILDKIT_MULTI_PLATFORM`, fixes the OCI `created` label, clamps layer mtimes with `rewrite-timestamp`, and fixes compression and exporter settings. `scripts/verify-reproducible-images.sh` builds the real target twice with separate pinned builders, no cache, and no default attestations, then compares the complete unpacked OCI-layout Merkle content, rejecting transport wrappers like `docker image save` as equality oracles. The mkosi installer lane adds an architecture-scoped deterministic seed, Dracut reproducible mode, a fixed zstd worker count, and sorted SHA-256 records; the firmware lane feeds the commit epoch into EDK2, U-Boot, and OP-TEE. Blocking two-build gates run on ARM64 for production and TEST-only dev OCI subjects, the installer's canonical unsigned root filesystem, initrd, and package manifest, and firmware unsigned components, with JSON evidence retained 30 days. Bytes that intentionally vary (the installer's fresh SoftHSM key and certificate, signed UKI, the QEMU TF-A `CREATE_KEYS=1` envelope, the RK3588 external-TPL-dependent final image) are recorded but excluded from the equality claim. Source: [refs/reproducible-builds-2026-07-22.md](https://raw.githubusercontent.com/yubi-OS/yubiOS/main/refs/reproducible-builds-2026-07-22.md).

## Layer 4: Signatures and attestations

Published OCI artifacts carry BuildKit-native provenance and SBOM attestations on the OCI index. [tests/verify-oci-attestations.sh](https://raw.githubusercontent.com/yubi-OS/yubiOS/main/tests/verify-oci-attestations.sh) verifies, always against the immutable digest and never a mutable tag: the cosign local-key signature against `cosign/yubios-omni157.pub`, the cosign-attached SPDX SBOM attestation (`--type spdxjson`), the cosign-attached SLSA v1.0 provenance attestation (`--type slsaprovenance1`, requiring the v1.0 `buildDefinition` shape, not the flat v0.2 one), and the BuildKit attestation children via `docker buildx imagetools inspect`. cosign v3.1.2 is the canonical signing binary (version-sensitive; SHA-512 pinned in [PINNED.md](https://raw.githubusercontent.com/yubi-OS/yubiOS/main/PINNED.md), last reviewed 2026-08-04). Sources: [tests/verify-oci-attestations.sh](https://raw.githubusercontent.com/yubi-OS/yubiOS/main/tests/verify-oci-attestations.sh), [PINNED.md](https://raw.githubusercontent.com/yubi-OS/yubiOS/main/PINNED.md), [refs/slsa-l3-sbom-cosign-integration-spec-2026-08-04.md](https://raw.githubusercontent.com/yubi-OS/yubiOS/main/refs/slsa-l3-sbom-cosign-integration-spec-2026-08-04.md).

Verification also runs at consume time: the ADR-031 GPU trust boundary requires a guest bootc image's digest to match a pinned reference and its SLSA provenance to verify against the expected builder id before any libvirt-class launcher may attach a PCI GPU. Source: [docs/ADR.md](https://raw.githubusercontent.com/yubi-OS/yubiOS/main/docs/ADR.md) (ADR-031).

## SLSA v1.0 Build L3 target

The OMN-157 integration spec ("yubiOS Production Proof & Release Gates", filed 2026-08-01) sets the target for `yubiOS-ci.yml`, `ci_mkosi-installer.yml`, and `ci_dev_image.yml`: SLSA v1.0 Build L3, SPDX 2.3 JSON SBOMs, cosign-signed attestations, and Rekor v2 entries, plus a `ci_attestation-verify.yml` verifier gate downstream consumers can re-run. Two framing facts are load-bearing. SLSA v1.0's Build track runs L0 to L3 only; there is no Build L4 (verified against the v1.0 spec, source: [slsa.dev/spec/v1.0/levels](https://slsa.dev/spec/v1.0/levels)). And L3's distinguishing requirement is a hardened, isolated builder the tenant project cannot tamper with; the canonical GitHub Actions path is the `slsa-framework/slsa-github-generator` reusable workflows on ephemeral GitHub-hosted runners, per the spec (SLSA's own guidance likewise encourages building on proven builder architecture rather than hand-rolling provenance, 0.79). Source: [refs/slsa-l3-sbom-cosign-integration-spec-2026-08-04.md](https://raw.githubusercontent.com/yubi-OS/yubiOS/main/refs/slsa-l3-sbom-cosign-integration-spec-2026-08-04.md).

## Rekor v2 posture

The transparency-log posture targets Sigstore Rekor v2, the tamper-resistant public ledger for signing metadata (Rekor's design goal per Sigstore's docs, 0.90, 0.91): a tile-backed, hash-only log with sharded inclusion proofs and TUF SigningConfig-driven endpoint discovery, verified via `cosign verify-attestation --rekor-tiles`. cosign added Rekor v2 upload and verification support in v2.6.0 (sigstore blog, 2025-10-10, 0.17), well below yubiOS's pinned v3.1.2 (version-sensitive). The spec's cross-cutting gap G-X-3 requires refreshing the TUF metadata cache on every CI run to avoid rotation-related failures. Sources: [refs/slsa-l3-sbom-cosign-integration-spec-2026-08-04.md](https://raw.githubusercontent.com/yubi-OS/yubiOS/main/refs/slsa-l3-sbom-cosign-integration-spec-2026-08-04.md), [blog.sigstore.dev/rekor-v2-ga](https://blog.sigstore.dev/rekor-v2-ga/) (0.17), [docs.sigstore.dev/logging/overview](https://docs.sigstore.dev/logging/overview/) (0.90).

## Open items

- Keyless OIDC cosign signing and Rekor v2 transparency-log entries are a post-launch follow-up. The current implementation is key mode: [cosign/signing-config.json](https://raw.githubusercontent.com/yubi-OS/yubiOS/main/cosign/signing-config.json) intentionally has no `rekorTlogUrls`, so verification uses `--insecure-ignore-tlog` with `--key`. Source: [tests/verify-oci-attestations.sh](https://raw.githubusercontent.com/yubi-OS/yubiOS/main/tests/verify-oci-attestations.sh).
- The L3 isolation gap is open: the release workflows build on rootless dockerd in the runner, not the isolated `slsa-github-generator` runners the spec requires (the spec's gap rollup counts this as the single biggest behavioral change, ~3 blocker gap rows; the spec is the Specify-phase output with Plan and Task phases deferred). Source: [refs/slsa-l3-sbom-cosign-integration-spec-2026-08-04.md](https://raw.githubusercontent.com/yubi-OS/yubiOS/main/refs/slsa-l3-sbom-cosign-integration-spec-2026-08-04.md).
- Rule 3 (`input.image.hasProvenance`) in [yubiOS.rego](https://raw.githubusercontent.com/yubi-OS/yubiOS/main/yubiOS.rego) stays commented out until `quay.io/fedora/fedora-bootc` ships provenance upstream.
- Full-image reproducibility for the final Rockchip image requires an approved immutable digest for the RK3588 external DDR/TPL blob, and month-later rebuildability requires immutable repository snapshots. Source: [refs/reproducible-builds-2026-07-22.md](https://raw.githubusercontent.com/yubi-OS/yubiOS/main/refs/reproducible-builds-2026-07-22.md).
