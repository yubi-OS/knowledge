## Execution model

The MVP is scoped for the **parallel-build-lanes** pattern: a spec, multiple build lanes working in parallel, and reconciliation. The one-pager lists four scope items in a deliberate order.

## Item 1: Python source of record

`spectral_standard.py`, stdlib only, containing:

- a mask-to-graph builder;
- a random-walk d_w estimator and a return-probability d_s estimator, both over pinned windows;
- a counting-exponent fit;
- the Einstein consistency verdict;
- a gasket graph builder;
- a selftest.

Including the gasket graph builder in the source of record matters: the gold family is generated by the same code that measures it, so calibration does not depend on an external fixture file that could drift.

## Item 2: exact-eigen gold

- Fukushima-Shima gasket eigenvalues, produced by the decimation recursion and **verified against a brute-force Jacobi eigen-solve** on level-2 and level-3 graphs.
- Analytic bands for the 1D chain (alpha = 1) and the 2D lattice (alpha = 2).
- Permutation nulls that **must** collapse alpha.

The cross-check is two independent routes to the same numbers. Decimation is fast and exact in principle; Jacobi is slow but general. Agreement on small levels licenses using decimation at larger levels.

The trivial bands (1D chain, 2D lattice) are the sanity floor. The permutation nulls are the integrity floor: if shuffling the series leaves alpha unchanged, the fit is reading sample size.

## Item 3: JS worker port and routes

- Routes under `/api/jev/corpus/spectral/*`.
- Following the taste-engine pattern: fixture parity, run rows of kind `spectral`.

The later SPEC refined the run-row kinds into `spectral-walk`, `spectral-series`, and `oracle`; the one-pager's single `spectral` kind is the earlier, coarser plan.

## Item 4: falsification harness, LAST

- Pre-registered bands.
- Gate windows checked against the pinned lattice **before** running, following the falsification-corpus skill's own rules.
- Live-route parity.

Placing the harness last is a sequencing choice, not a priority statement. The harness needs a working instrument and a deployed route to test against. What must happen early is pre-registration: bands are written down before any measurement, even though the harness that enforces them is assembled at the end.

## Dependency graph

| Item | Depends on |
|---|---|
| 1. Python source | nothing |
| 2. Exact-eigen gold | 1 (gasket builder, eigen routines) |
| 3. JS port + routes | 1 (reference), 2 (fixtures) |
| 4. Harness | 1, 2, 3 (needs live route for parity) |

Items 1 and 2 can be built by separate lanes against a shared interface; item 3 can start as soon as item 1's interfaces are fixed.

## Scope boundaries inside the MVP

The MVP measures. It does not:

- actuate a lens;
- feed routing bands;
- expose an intake product surface;
- deploy any new model;
- retune any D window or coverage.

Those are the not-doing items (doc 05).

The SPEC kept the shape and pinned what the one-pager left open: walker count (64), PRNG (mulberry32), r2 gate (0.98), series window ([N/8, N/2]), and the Einstein band (0.10).

## Acceptance implied by the scope

An MVP that passes would show: exact gasket exponents recovered within bands; integer d_s on chain and lattice; collapse under permutation; byte-level parity between Python and JS; and a live route that returns the same numbers as the local reference.
