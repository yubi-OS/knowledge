# 05. Parallel subagent authoring

Scope: Fanning out one author subagent per doc: the returned-markdown contract, citation discipline where every factual claim carries its source and weight, the thin-dig redo rule, and skip-as-gap.

The authoring phase of a mint fans out one subagent per doc. The pattern is documented across the agent-architecture literature. LlamaIndex's developer documentation describes the orchestrator pattern in which an orchestrator agent chooses which sub-agent to call next, with those sub-agents exposed to it as tools (weight 0.93, https://developers.llamaindex.ai/python/framework/understanding/agent/multi_agent/). In a mint, the orchestrator does not pick sub-agents dynamically; it dispatches all of them up front, one per outline entry, which makes the fan-out deterministic.

Fan-out semantics for research tasks are described consistently: dispatch N sub-agents in parallel, each with its own isolated context window, returning distilled summaries to the main thread for synthesis (weight 0.24, weak backing, https://www.agentpatterns.ai/patterns/multi-agent/sub-agents-fan-out/). Isolated context matters here because each author sees only its own doc's dig results, its own scope line, and its own queries, so one doc's noise cannot contaminate another. A production guide lists the five core patterns, orchestrator/worker, pipeline, fan-out, debate, and routing, with architecture diagrams and cost analysis (weight 0.12, weak backing, https://explainx.ai/blog/multi-agent-orchestration-patterns-guide-2026), and a second survey enumerates six patterns including hierarchical, swarm, and mesh with a decision framework and failure modes (weight 0.27, weak backing, https://www.glukhov.org/ai-systems/architecture/multi-agent-orchestration-patterns/). A mint uses the fan-out cell of that taxonomy with a hard simplification: sub-agents return markdown to the orchestrator and never touch the repository themselves.

The citation contract inside each sub-agent is grounded generation. The pattern is defined as forcing an LLM's output to be derivable from a supplied set of retrieved sources, with citations attached, and it is described as the standard defense against hallucination in retrieval pipelines (weight 0.45, weak backing, https://www.zeroentropy.dev/concepts/grounded-generation/). The operational version has three checks: generation with grounding, a groundedness check where every claim must trace to a source chunk, and citation verification where the cited sources exist and contain the claim (weight 0.14, weak backing, https://blog.prompt20.com/posts/ai-hallucinations/). A mint compresses this to one contract line: a claim with no source is deleted, not softened, and every kept claim carries its source URL plus the jev weight that backed it.

Two measurable quantities come out of that literature: citation precision, of the citations given how many actually support their claim, and citation recall, of the claims that needed a source how many got a correct one (weight 0.07, weak backing, https://dev.to/dev48v/grounding-and-citations-making-llm-answers-you-can-actually-verify-255i). The mint's audit pass maps onto citation precision: the reviewer re-reads each doc checking that the cited URL's snippet actually supports the sentence. The definitional endpoint of this discipline is the citation-grounded system, where every factual claim in an output is tied to a verifiable source (weight 0.13, weak backing, https://edtek.ai/kb/citation-grounded-llm/).

The thin-dig rule is the honesty valve. If a subtopic's dig is too thin to author honestly, the dig is redone with different queries, up to 2 redos, each logged; fetching primary sources directly to fill a thin dig is explicitly forbidden because it bypasses the weighting pipeline. If the dig is still thin after redos, the doc is skipped and recorded as a gap in the README. Cannot-author is treated as a success signal, not a failure: a documented gap stub is preferable to padded prose. In this corpus's observed run, 9 of 9 subtopic digs returned at least 11 weighted results, so no redo digs and no skips were needed; the one weighting redo was a client-side parse failure, not a thin dig.

## Sub-claims

1. The orchestrator pattern exposes sub-agents as callable units of the orchestrator (weight 0.93, https://developers.llamaindex.ai/python/framework/understanding/agent/multi_agent/).
2. Fan-out gives each sub-agent an isolated context and returns distilled summaries for synthesis (weight 0.24, weak backing, https://www.agentpatterns.ai/patterns/multi-agent/sub-agents-fan-out/).
3. Fan-out is one cell of a documented pattern taxonomy that also includes orchestrator/worker, pipeline, debate, and routing (weight 0.12, weak backing, https://explainx.ai/blog/multi-agent-orchestration-patterns-guide-2026; weight 0.27, weak backing, https://www.glukhov.org/ai-systems/architecture/multi-agent-orchestration-patterns/).
4. Grounded generation forces output to be derivable from retrieved sources with citations attached (weight 0.45, weak backing, https://www.zeroentropy.dev/concepts/grounded-generation/).
5. Citation precision and citation recall are the two measurable quantities of grounded output (weight 0.07, weak backing, https://dev.to/dev48v/grounding-and-citations-making-llm-answers-you-can-actually-verify-255i).
6. Thin digs are redone with different queries up to 2 times, then skipped and recorded as gaps; no direct primary-source fallback (mint contract, applied in this run: 0 dig redos, 0 skips).
