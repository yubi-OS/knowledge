# 02. Decision model outline validation

Scope: Using a typed decision model (score/choice metrics returning probabilities) to validate which outline docs are load-bearing before spending dig budget: the cheap-kill pruning principle.

The mint pipeline validates its outline with a typed decision model before any digging starts, on the theory that pruning an outline costs one request while pruning a corpus costs the whole run. The decision-model pattern that justifies this is documented in production docs: a decision model evaluates supplied evidence against a rubric and returns a typed answer, either a choice, a score, or a Boolean probability, and is intended for bounded judgments such as routing a request or scoring its urgency (weight 0.86, https://docs.openclaw.ai/concepts/decision-models). Outline validation is exactly that shape of bounded judgment: per subtopic, one score on a fixed 3-point ordinal scale, with the criteria spelled out in the question.

The LLM-as-a-judge literature describes the same mechanism from the evaluation side. Langfuse's documentation describes rubric-guided LLM-as-a-judge evaluation: using a large language model to automatically score, evaluate, and monitor outputs at scale with structured rubric assessments (weight 0.74, https://langfuse.com/docs/evaluation/evaluation-methods/llm-as-a-judge). An outline validation request is a rubric-guided judge pass where the "output" being judged is a proposed subtopic and the rubric is the load-bearing criteria list.

Two caveats from the same literature matter for anyone wiring this up. Polyaxon's writeup argues that an LLM judge can turn a rubric into structured labels, scores, pairwise preferences, or explanations, but that the judge is itself an evaluator which must be tested, versioned, and monitored like any other model (weight 0.37, weak backing, https://polyaxon.com/blog/llm-as-a-judge/). AutoRubric codifies the measurement-theory position: analytic rubrics with atomic criteria, multi-judge panels, explicit uncertainty handling, and validation against human judgments (weight 0.21, weak backing, https://autorubric.org/). Domain-specific rubric evaluation also carries documented biases that require empirical validation in context (weight 0.14, weak backing, https://medium.com/@adnanmasood/rubric-based-evals-llm-as-a-judge-methodologies-and-empirical-validation-in-domain-context-71936b989e80).

The practical contract that the mint pipeline draws from this: the judge must return a typed, parseable answer (a numeric score, not prose), the criteria must be stated in the request itself rather than implied, and the full raw answer including probabilities must be archived so the pruning decision is auditable after the fact. In the observed run, the score answers arrived as continuous values on the 0 to 2 scale (for example 1.9457, 1.2306, 1.0606), which is more informative than integers because it separates "clearly load-bearing" from "barely marginal" within the same band.

A second observation from this dig concerns what the weighting model does with the surrounding ecosystem. Multiple "Decisions API" marketing and aggregator sites were collected and scored very low, between 0.08 and 0.37 (for example weight 0.08, https://decisionapi.net/; weight 0.23, https://autorubric.org/docs/api/decision-models/), while the substantive documentation pages scored highest. This is the behavior a mint wants: marketing surfaces get pruned by the weighting pass even when their titles look relevant.

## Sub-claims

1. Decision models return typed answers: choice, score, or Boolean probability, for bounded judgments (weight 0.86, https://docs.openclaw.ai/concepts/decision-models).
2. Rubric-guided LLM-as-a-judge scores outputs at scale with structured criteria (weight 0.74, https://langfuse.com/docs/evaluation/evaluation-methods/llm-as-a-judge).
3. The judge is itself an evaluator that must be tested and versioned; rubric evals carry biases requiring domain validation (weight 0.37, weak backing, https://polyaxon.com/blog/llm-as-a-judge/; weight 0.14, weak backing, https://medium.com/@adnanmasood/rubric-based-evals-llm-as-a-judge-methodologies-and-empirical-validation-in-domain-context-71936b989e80).
4. Analytic rubrics with atomic criteria plus explicit uncertainty handling is the measurement-theory-backed design (weight 0.21, weak backing, https://autorubric.org/).
5. Continuous score answers are more informative than integers for pruning decisions (observed in this run's validation answers: 1.9457, 1.2306, 1.0606 on the 0 to 2 scale).
