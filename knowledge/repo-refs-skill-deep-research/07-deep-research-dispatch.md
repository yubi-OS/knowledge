# 07 - Parallel Deep-Research Dispatch for Gap Filling

Scope: the Mode C dispatch stage: fanning out parallel research subagents to fill sparse cells, the orchestrator-worker pattern that structures it, and the synthesis and write-through rules.

## The canonical production system

The reference implementation of parallel research dispatch is Anthropic's multi-agent research system, documented on their engineering blog: the Research feature uses multiple Claude agents to explore complex topics more effectively, and the writeup shares the engineering challenges and lessons learned building it (https://www.anthropic.com/engineering/multi-agent-research-system, jev weight 0.9584, high). The measured claim that justifies the fan-out comes from their internal evaluations as quoted in independent commentary: a multi-agent system with a stronger lead agent and subagents outperformed a single-agent setup by 90.2% on their internal research eval, and multi-agent research systems excel especially for breadth-first queries that involve pursuing multiple independent directions simultaneously (https://simonwillison.net/2025/Jun/14/multi-agent-research-system/, jev weight 0.6519, high). That is exactly the shape of a sparse-cell dispatch: independent gaps, explored in parallel.

Breadth-first parallelism compresses search space: running several agents in parallel allows breadth-first exploration, compresses large search spaces into manageable insights, and reduces the risk of missing key information (https://blog.bytebytego.com/p/how-anthropic-built-a-multi-agent, jev weight 0.1968, weak). A deeper architectural walkthrough describes the same system in terms of orchestrator-worker patterns, prompt engineering principles, and lessons from scaling the Research feature, including its 15x token usage relative to chat (https://cuizhanming.com/anthropic-multi-agent-research-architecture/, jev weight 0.2291, weak). The cost number is weak-backed and should be treated as an order-of-magnitude caution, not a measured figure.

## The orchestrator-worker pattern

The pattern that structures the dispatch is documented as a first-class recipe in the Claude Cookbook: the orchestrator-workers pattern has a central LLM analyze each unique task and dynamically determine the best subtasks to delegate to specialized worker LLMs, in contrast to manual prompting or hardcoded parallelization that generates the same variations regardless of context (https://platform.claude.com/cookbook/patterns-agents-orchestrator-workers, jev weight 0.9249, high). The reference notebook spells out the two phases: an analysis and planning phase in which the orchestrator LLM receives the task and context, analyzes what approaches would be valuable, and generates structured subtask descriptions in XML format, followed by worker execution (https://github.com/anthropics/claude-cookbooks/blob/main/patterns/agents/orchestrator_workers.ipynb, jev weight 0.9342, high). The pattern's canonical definition traces to Anthropic's Building Effective Agents: a central LLM plans, dispatches subtasks to workers, then aggregates (https://buildingeffectiveagents.com/patterns/orchestrator-worker/, jev weight 0.5267, high).

Where fan-out sits in the wider taxonomy: a practical guide to multi-agent orchestration patterns for production systems lists six patterns, orchestrator-worker, sequential pipeline, fan-out, hierarchical, swarm, and mesh, with a decision framework, failure modes, and cost analysis (https://www.glukhov.org/ai-systems/architecture/multi-agent-orchestration-patterns/, jev weight 0.52, high).

## Fan-out mechanics and the synthesis boundary

The fan-out literature converges on a consistent shape. Fan-out dispatches N sub-agents in parallel, each with its own isolated context window, returning distilled summaries to the main thread for synthesis (https://www.agentpatterns.ai/patterns/multi-agent/fan-out-out/, jev weight 0.38, weak). In the synthesis variant, each spawned agent produces a distinct solution, a synthesis agent critiques all outputs against defined criteria and assembles a merged result, and a validation pass reviews the merged output before acceptance (https://www.agentpatterns.ai/patterns/multi-agent/fan-out-synthesis/, jev weight 0.44, weak). A caution accompanies the pattern: fan-out synthesis is the right tool for high-stakes decisions, but the synthesis agent is the single highest-risk component, and getting it wrong makes the output worse than the best single attempt (https://learn.agentpatterns.ai/multi-agent/fan-out-and-synthesis/, jev weight 0.39, weak).

The sharpest failure mode is a context-relay hazard: when an orchestrator fans out N independent subagents and one of those same agents is also expected to synthesize or file everyone's findings, the synthesizing agent does not automatically see its siblings' outputs just because they ran in the same round, because each subagent only has the context given in its own prompt (https://gist.github.com/Magubot/47527bf1d9665593d73aa9d44f2222fc, jev weight 0.13, weak). The design consequence is explicit relay: synthesis must receive the collected outputs as input, never assume shared context.

## Assembling the dispatch stage

For a sparse-cell fill cycle, the sourced design is: the orchestrator (the cycle runner) holds the gap map and generates one structured subtask description per sparse cell (https://github.com/anthropics/claude-cookbooks/blob/main/patterns/agents/orchestrator_workers.ipynb, jev weight 0.9342, high); the N fills run in parallel with isolated contexts, which suits breadth-first independent gaps (https://simonwillison.net/2025/Jun/14/multi-agent-research-system/, jev weight 0.6519, high); each subagent returns a distilled output, not its full transcript (https://www.agentpatterns.ai/patterns/multi-agent/fan-out-out/, jev weight 0.38, weak); synthesis is a separate deliberate step that receives every collected output explicitly, because shared context cannot be assumed (https://gist.github.com/Magubot/47527bf1d9665593d73aa9d44f2222fc, jev weight 0.13, weak); and the synthesized docs are written back into the archive as the cycle's output. Token cost is the acknowledged trade-off of the pattern, with weak-backed figures suggesting multi-fold token spend versus single-agent chat (https://cuizhanming.com/anthropic-multi-agent-research-architecture/, jev weight 0.2291, weak), so dispatch should be bounded to the sparse cells the cycle actually needs, not the whole corpus.
