# 05 Exposing Deterministic Math as API Routes on a Cloudflare Worker

Scope: the API surface layer: how a Cloudflare Worker routes requests to a dedicated math engine, the schema the engine's run records need, and the idempotency, auth, and purity guardrails that keep the math endpoint trustworthy.

## Routing on a Worker

Cloudflare Workers route by URL pattern: routes map URL patterns to Workers so your code runs on matching requests [1](https://developers.cloudflare.com/workers/configuration/routing/routes/) (weight 0.08, weak backing). Cloudflare's own best-practices guidance collects code patterns and configuration guidance for building fast, reliable, observable, and secure Workers [2](https://developers.cloudflare.com/workers/best-practices/workers-best-practices/) (weight 0.25, weak backing). Tutorial treatments of Workers routing cover URL patterns, practical examples, and the fetch handler plus env bindings and secrets pattern [3](https://tutorials.dodatech.com/cloudflare/workers-routing/) (weight 0.36, weak backing), [4](https://stackharbor.com/en/knowledge-base/cf-workers-first-script-and-routes/) (weight 0.13, weak backing). One operational detail matters for a sub-path API: if a route is configured to a hostname, a DNS record must exist for that hostname so it resolves externally [5](https://docs.kabirsikand.com/workers/platform/routing/routes/) (weight 0.16, weak backing). Workers can also host more than request handling; the email service, for example, is reachable directly from Workers via bindings, from any platform via the REST API, or over authenticated SMTP [6](https://developers.cloudflare.com/email-service/) (weight 0.54).

Inside a Worker, an internal dispatcher (a plain if-chain or small router over `URL.pathname`) is what separates an `/api/...` namespace from other traffic; a dedicated dispatch arm placed before a legacy catch-all is the standard way to add a new API family without disturbing existing behavior [2](https://developers.cloudflare.com/workers/best-practices/workers-best-practices/) (weight 0.25, weak backing).

## Idempotency for repeat calls

An audit endpoint is read-mostly, but a run-recording endpoint is not, and retries are inevitable. The Idempotency-Key header is the standard mechanism: it lets the server recognize a repeated request instead of performing the same operation twice [7](https://restfulapi.net/idempotency-keys-in-rest-apis/) (weight 0.78). Stripe's API reference defines the contract precisely: "the API supports idempotency for safely retrying requests without accidentally performing the same operation twice" [8](https://docs.stripe.com/api/idempotent_requests) (weight 0.92). Implementation subtleties decide whether the design is correct: server-side key storage, what the key is scoped to, and what a repeat returns [9](https://algomaster.io/learn/api-design/idempotency-keys) (weight 0.26, weak backing), [10](https://vabs.github.io/2026/04/15/idempotency-keys-in-api-design/) (weight 0.21, weak backing), [11](https://statuscodefyi.com/guides/api-idempotency-design-guide/) (weight 0.25, weak backing). When the backing store is durable and shared, deduplication can live next to the data: implementations with Postgres, Redis, and Cloudflare Durable Objects all exist, and the cost of not deduplicating is duplicated side effects [12](https://metasora.com/blog/idempotency-keys-api-design/) (weight 0.13, weak backing).

## Schema, auth, and purity

A recording API needs a storage schema owned by the API itself. In the Jev Corpus engine the routes module exports the DDL (`CORPUS_SCHEMA_DDL`) plus an idempotent `ensureCorpusSchema` applied at request time, so a fresh deployment can serve immediately and repeat DDL is harmless. The runs table records every audit/lens/classify invocation so a later cycle can diff against previous measurements. (Source: the yubiOS refs source document "Jev Corpus", 2026-10-01.)

The purity guardrail is the unusual and load-bearing one: because these routes expose deterministic math, the routes test suite monkeypatches `fetch` to throw, so any code path that attempted a network call from inside a math route would fail the suite rather than silently introduce nondeterminism. Auth is enforced at the route boundary by the existing platform gate, not inside the math. (Source: the yubiOS refs source document "Jev Corpus", 2026-10-01.)

## Application in the Jev Corpus engine

The engine's routes lane ships `handleJevCorpus` as one dispatch arm, wired in ahead of the legacy catch-all, with the schema, idempotent run recording (`/runs`), and health/selftest endpoints. Live verification exercised exactly these properties: a `/audit` round-trip followed by an identical repeat returning `cached: true`, confirming idempotency in production, and `/health` plus `/selftest` confirming module integrity. (Source: the yubiOS refs source document "Jev Corpus", 2026-10-01.)
