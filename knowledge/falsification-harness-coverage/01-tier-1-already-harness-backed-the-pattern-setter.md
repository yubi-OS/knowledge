## What "harness-backed" means here

The ground source defines a falsification harness as six components, taken from the falsification-corpus skill: pre-registered pinned parameters and predicted bands written BEFORE measurement; a synthetic known-answer gold corpus; gate windows verified against the actual scale lattice before the run; committed regression anchors; live-route parity between the worker port and the Python source of record; and a real-data pass protocol whose confound controls are named in advance. Tier 1 is the set of endpoints that already satisfy that definition. They are called the pattern-setters because every Tier 2 build is expected to copy their shape: a synthetic gold family with exact closed-form answers, a pre-registered gate, and an `anchors.json` machine-readable record, all failing loud rather than soft.

The framing is Popperian. A harness does not prove an instrument correct; it gives the instrument a chance to fail on inputs whose answer is known. The POPPER project describes the same stance for agentic hypothesis validation, "guided by Karl Popper's principle of falsification" [GitHub - snap-stanford/POPPER: Automated Hypothesis Testing with ...](https://github.com/snap-stanford/POPPER) (clef weight: 0.4053) (weak backing, clef weight < 0.5), and the stgem library frames black-box falsification and test generation for cyber-physical systems as a reusable tooling layer [stgem: A software library to develop falsification and test generation ...](https://www.sciencedirect.com/science/article/pii/S0167642325001510) (clef weight: 0.3056) (weak backing, clef weight < 0.5). A practitioner essay makes the induction point bluntly: software testing is "induction with a CI pipeline", a finite run of cases inferring a general claim [The Frog That Lived: Let's learn about falsification. - DEV Community](https://dev.to/sheraz4194/the-frog-that-lived-lets-learn-about-falsification-4l7e) (clef weight: 0.1891) (weak backing, clef weight < 0.5). All three are weak backing here; the load-bearing definitions come from the ground source.

## The six Tier 1 endpoints

| Endpoint family | Harness evidence recorded in the source |
|---|---|
| `POST /api/jev/corpus/spectral/walk`, `/spectral/series`, `GET /spectral/selftest` | 15/15 gold PASS plus 61 anchors; walk gold pinned at merged-gasket level 6 |
| `POST /api/jev/corpus/oracle` | Gold families with exact closed-form d_f and d_w; Einstein zero-false-"consistent" held 11/11 on real data |
| `POST /api/jev/corpus/lens/correct`, `GET /lens/selftest` | 75/75 falsification PASS; pre-registration plus anchors; cross-talk envelope |
| `POST /api/jev/corpus/taste/edge-standard` | Falsification-corpus-validated pipeline; the v1 gasket gate FAIL caught the design error before real data; 4-fixture parity |
| `POST /api/map/control` | Is itself the positive-control falsification endpoint (seeded splice CHANGEs on the frozen frame) |
| `POST /api/map/admission`, `/rayleigh`, `/azimuth`, `/axis-redundancy` | Matched-null trials: fixed-margin curveball null, positive controls, calibration pack |

Three patterns stand out. First, closed-form answers: the spectral and oracle gold families have exact fractal and walk dimensions (d_f, d_w), so a gate can be an equality within tolerance rather than a judgment. Second, the edge-standard case is the proof that the discipline pays: its v1 gasket gate failed on synthetic data and exposed a design error before any real-data verdict was issued. Third, the map family splits cleanly into a positive control (`/api/map/control`, which plants known changes) and matched-null trials (which establish what "no effect" looks like under a fixed-margin curveball null).

## Why determinism matters for gold corpora

Every Tier 1 harness relies on reproducible synthetic inputs, which in practice means a seeded pseudo-random generator so that a gold corpus can be regenerated byte for byte. The dig surfaced Mulberry32 as a common choice for deterministic fixtures: a 32-bit generator with a single 32-bit state, combining a Weyl sequence with MurmurHash3-style mixing [Mulberry32 | Hawkynt](https://hawkynt.github.io/Cipher/docs/algorithms/random-number-generators/mulberry32.html) (clef weight: 0.3301) (weak backing, clef weight < 0.5), recommended for "procedural generation, simulations, or test fixtures" [Mulberry32: A Tiny, Fast, Deterministic RNG - 4rknova.com](https://www.4rknova.com/blog/2026/03/01/mulberry32-rng) (clef weight: 0.1898) (weak backing, clef weight < 0.5) and explained as a pragmatic seeded PRNG for JavaScript [Understanding how to use Mulberry32 to achieve deterministic randomness ...](https://www.emanueleferonato.com/2026/01/08/understanding-how-to-use-mulberry32-to-achieve-deterministic-randomness-in-javascript/) (clef weight: 0.1055) (weak backing, clef weight < 0.5). The strongest result in this dig, the author's own gist, adds a caveat that matters for gold-corpus design: Mulberry32 "isn't equidistributed" and cannot produce about 1/3 of all possible uint32 values [Mulberry32 PRNG · GitHub](https://gist.github.com/tommyettinger/46a874533244883189143505d203312c) (clef weight: 0.7420). The ground source does not name a PRNG for Tier 1; the practical lesson is that whichever generator a harness uses must be pinned in the pre-registration, and its coverage limits must not be mistaken for a property of the instrument under test.

## The standing lesson behind Tier 1

The source motivates the whole list with the refs3 lesson: negative verdicts earned under a noisy instrument are provisional, not terminal, because the free-prose scorer band was 6 to 8 times the true effect. A falsification corpus shrinks the instrument BEFORE a verdict is trusted instead of re-litigating it afterward. Tier 1 endpoints are the ones where that shrinking has already happened, and their anchors are what later rounds check against.
