# 03 - in-toto and SLSA L3 link attestations

Scope: in-toto link attestations and SLSA L3 provenance as the supply-chain leg of the evidence shape. Ground source: the yubiOS skill names "in-toto SLSA L3 link attestations" as one of the three attestation frameworks it anchors.

## What in-toto attestations are

The in-toto Attestation Framework's core is a specification that defines the format for in-toto attestations and the metadata they contain. Alongside the spec it publishes a set of attestation predicates, which are metadata formats vetted by the maintainers to cover a number of common use cases, plus protobuf definitions of the spec and language bindings for tooling integration (source: https://github.com/in-toto/attestation, jev weight 0.80).

In the evidence shape of doc 02, an in-toto attestation is the signed statement that plays the quote role on the supply-chain leg: a subject (artifact digest) bound to a predicate (what happened to it) by an attestor's signature.

## What SLSA provenance is

SLSA defines provenance as verifiable information that can be used to track an artifact back, through all the moving parts in a complex supply chain, to where it came from: "the verifiable information about software artifacts describing where, when, and how something was produced" (source: https://slsa.dev/provenance/, jev weight 0.89). SLSA provenance v1 is specified with a protobuf definition that "prioritizes being a human-readable summary of the schema"; a version of the protobuf useful for code generation is maintained in the in-toto attestation repository (source: https://slsa.dev/provenance/v1, jev weight 0.89). This is the concrete seam between the two frameworks: SLSA provenance is expressed as an in-toto attestation predicate.

## What Level 3 adds

GitLab's implementation documentation states the key differences between level 2 and level 3 provenance attestation are isolation and "unforgeable" requirements (source: https://docs.gitlab.com/ci/pipeline_security/slsa/level_3/, jev weight 0.84). Level 3 means the provenance was generated by a build platform whose build service is isolated from user-controllable state, so the provenance is not merely signed but generated in a hardened environment. GitLab's internal design document for SLSA Level 3 describes the verification flow: download the required verification policy, then verify the signed provenance against the downloaded artifact (source: https://handbook.gitlab.com/handbook/engineering/architecture/design-documents/slsa_level_3/, jev weight 0.74).

GitHub's artifact attestation offering makes the same journey concrete for a different platform: SLSA provides "a comprehensive, step-by-step methodology for building integrity and provenance guarantees into your software supply chain," and GitHub Artifact Attestations are positioned as simplifying the path to SLSA Level 3 (source: https://github.blog/enterprise-software/devsecops/enhance-build-security-and-reach-slsa-level-3-with-github-artifact-attestations/, jev weight 0.64).

## Reading these as the supply-chain leg of the evidence shape

Mapping to the 4-component shape:

- Quote: the signed in-toto attestation (the attestor's signature over subject and predicate).
- Measurement: the provenance content itself, the build steps, materials, and environment recorded in the predicate.
- Evidence bundle: the attestation document, typically attached to the artifact in an OCI registry.
- Rekor v2 anchor: the transparency-log entry that timestamps the attestation so its existence and content are publicly verifiable later (doc 05).

## Why yubiOS needs this leg

Boot attestation (doc 01) and confidential-VM attestation (doc 04) prove properties of a running machine. Neither proves that the artifact the machine booted was produced by a trustworthy pipeline. The in-toto / SLSA leg closes that gap: for yubiOS the relevant artifacts are the bootc OCI images themselves. A signed SLSA L3 provenance on the image ties the booted composefs-verified content back to the build that produced it, which is the supply-chain half of "the machine is running what we meant, built the way we meant."
