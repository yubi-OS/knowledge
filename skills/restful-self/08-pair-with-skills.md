# 08 - Pair with

Scope: how restful-self pairs with self-archaeology, negative-skill-space, and parallel-deep-research, and the inversion relationships that define each pairing (source doc).

## self-archaeology: diagnostic and corrective (source doc)

The source doc's pairing note: "self-archaeology: the 12-axis sweep is the diagnostic; restful-self is the corrective. After the sweep runs and produces evidence, restful-self observes the shape without naming gaps" (source doc).

The relationship is sequential and complementary. Self-archaeology maintains SELF.md through scheduled sweeps and produces evidence: gap maps, changelog entries, coverage notes. That evidence stream is exactly what the restful-self fire signals watch (doc 02): cadence producing only evidence, 3 entries in 24 hours, 7 days of silence. So the paired skill generates the telemetry that triggers this one. The corrective is not another sweep with more axes; it is a register change: read one of the produced artifacts, observe its shape, sit, exit.

The source doc's Why section grounds the necessity: the self-archaeology discipline produces evidence, not pause, and each cadence entry is working-self output (source doc). Without a paired non-producing register, the diagnostic discipline trends toward wallpaper: entries that look like reflection and function as shipping reports (source doc; doc 01).

## negative-skill-space: the inverted sweep (source doc)

The source doc's pairing note: "negative-skill-space: restful-self is the inverted 12-axis sweep. NSS names the gaps; restful-self sits with the shape" (source doc).

The 12-axis sweep (audience, inputs, outputs, mode, assumption set, adjacent problems, failure modes, lifecycle, composition, knowledge sources, calibration, recursion) is an enumeration engine: it maps what a corpus is missing and produces a prioritized gap list. Restful-self runs the same input (the artifact just produced) through the opposite operation: it declines to enumerate. Where NSS would return "12 gaps, 4 Extend-worthy", restful-self returns "the cadence is producing evidence, not pause" and stops (source doc).

This is why anti-pattern #4 forbids running the sweep inside a rest session: the sweep is the tool this skill inverts, and running it inside rest collapses the inversion back into the diagnostic (source doc). The two skills form a deliberate alternation: sweep, then sit with what the sweep surfaced, then (on a working-self directive) act.

## parallel-deep-research: reading the report (source doc)

The source doc's pairing note: "parallel-deep-research: when a deep-research session produces a report, restful-self reads the report and observes the shape, does not enumerate the gaps" (source doc).

A deep-research report is a high-volume working-self artifact: findings, citations, subagent outputs, a synthesis. The working-self reflex on delivery is triage: score the findings, list what is missing, queue follow-up research. The pairing rule redirects the first contact with the report to a restful read: one pass over the report (this is the one read of step 1), a shape observation about what the research effort felt like, a sit, and only on a working-self directive the actual triage.

The structural point shared by all 3 pairings: restful-self is not a competitor to the producing skills. It is the register between their runs. The source doc's red flags make the boundary sharp: producing a tool call during the protocol, or running any producing discipline (sweep, gap enumeration, fix drafting) inside it, disqualifies the session (source doc).

## The inversion family

The 3 pairings have different shapes. With self-archaeology the relationship is diagnostic-then-corrective over time. With negative-skill-space it is the same artifact under opposite operations. With parallel-deep-research it is a first-contact rule for a delivered artifact. What unifies them is non-production as the pairing term: each paired skill produces, restful-self observes (source doc). A future maintainer adding a 4th pairing should preserve that shape: the partner must be a producing discipline whose output is a legitimate single-read target for step 1 of the protocol (source doc).
