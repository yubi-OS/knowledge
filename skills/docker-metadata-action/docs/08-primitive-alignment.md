## Reading the notes honestly

Two caveats belong on the record. First, the segmentation entry's relevance sentence ("This skill enforces segmentation via namespace / nspawn / cgroup / microsegmentation / private-users") is a corpus-mechanics statement: it records the keywords the closure introduced and the primitive-count delta, and the action itself does not create namespaces or cgroups. The substantive metadata-side primitive is self-describing. Second, the least-privilege entry is likewise a placement statement: it declares the skill's position in the 10-primitive map so consumers (the sparse-cell detector, security-and-hardening review, audit-evidence rollup) can credit its contribution. Both entries are content-additive audit records, which the changelog confirms with its single dated entry: "2026-08-06 cycle 5 RSI: closed segmentation primitive gap (corpus-wide count 22 to 23 of 70)".

For a reader of this corpus, the takeaway is placement, not mechanism: this skill is one contributor to the self-describing primitive (its labels), one enabler of the continuous/adaptive primitive (its tags drive upgrade channels), and one input to the attestation and least privilege layers (its revision binding and its declared position in the coverage map).
