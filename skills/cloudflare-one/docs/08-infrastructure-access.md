# 08 - Infrastructure Access

Scope: Zero Trust Infrastructure Access (ZTIA) for SSH, short-lived certificates, Browser Rendering for clientless SSH, RDP, and VNC, Audit SSH command logging, and the routing rule for protocols with no Access equivalent.

Grounding spine: source doc `yubi-OS/yubiOS skills/cloudflare-one/SKILL.md`.

## ZTIA: the purpose-built SSH offering

The source doc designates [Zero Trust Infrastructure Access](https://developers.cloudflare.com/cloudflare-one/access-controls/applications/non-http/infrastructure-apps/) as the purpose-built offering for SSH access through the device client, providing capabilities not available through self-hosted apps (source doc). The current docs detail what those capabilities are: Access for Infrastructure adds application-level policies with per-target and per-username controls, plus SSH command logging, and it replaces traditional SSH keys with short-lived certificates issued to users based on the token generated by their Access login ([SSH with Access for Infrastructure](https://developers.cloudflare.com/cloudflare-one/networks/connectors/cloudflare-tunnel/use-cases/ssh/ssh-infrastructure-access/), weight 0.89).

The naming history is on the [Cloudflare blog](https://blog.cloudflare.com/intro-access-for-infrastructure-ssh/): Access for Infrastructure, BastionZero's integration into Cloudflare One, applies Zero Trust controls to servers, databases, Kubernetes clusters, and more, with short-lived SSH access as the first available feature of the integration (weight 0.81).

The skill's rule is direct: use Infrastructure Access apps for SSH when the device client is deployed (source doc).

## Short-lived certificates

The source doc's requirement: short-lived certificates need CA configuration on the target host and `sshd` configured to trust the Cloudflare CA public key, and the [short-lived certificate setup](https://developers.cloudflare.com/cloudflare-one/identity/users/short-lived-certificates/) docs must be retrieved before configuring (source doc). The mechanics visible in the docs mirror: a certificate public key is generated in the dashboard under Zero Trust, Access controls, Service credentials, SSH, by selecting Add a certificate, choosing the Access application that represents the SSH server, and selecting Generate certificate ([short-lived certificates (legacy)](https://developers.cloudflare.com/cloudflare-one/access-controls/applications/non-http/short-lived-certificates-legacy/), weight 0.87). Note the docs mirror labels this flow legacy, which is consistent with the source doc steering SSH work toward ZTIA apps when the device client is present.

## Browser Rendering: clientless access

[Browser Rendering](https://developers.cloudflare.com/cloudflare-one/access-controls/applications/non-http/browser-rendering/) provides clientless SSH, RDP, and VNC through the browser without requiring the device client (source doc; the docs page confirms the surface, weight 0.91). The source doc adds the capability detail: clientless RDP includes session recording and file transfer controls. Clientless access is for cases where a device client cannot be installed: contractors, partner access, unmanaged devices. It is typically not the default for managed users who already have the client installed (source doc).

The VNC use case has its own docs surface: [VNC with browser rendering](https://developers.cloudflare.com/cloudflare-one/networks/connectors/cloudflare-tunnel/use-cases/vnc-browser-rendering/) (weight 0.9). A secondary blog source describes browser-based RDP as well ([browser-based RDP](https://blog.cloudflare.com/browser-based-rdp/), weight 0.64).

## Audit SSH

[Audit SSH](https://developers.cloudflare.com/cloudflare-one/networks/connectors/cloudflare-tunnel/use-cases/ssh/ssh-infrastructure-access/#enable-ssh-command-logging) is a Gateway Network policy action that logs SSH commands without blocking, and it requires the session to be proxied through Cloudflare (source doc). This is a distinct mechanism from ZTIA's built-in command logging: Audit SSH is a Gateway-side observation layer, usable without converting the app to an Infrastructure Access application.

## Protocols without an Access equivalent

The source doc closes the subtopic with a scope limit: for kubectl and database access behind private networks, use the device client with private destination routing. There is no Infrastructure Access or browser-rendered equivalent for arbitrary TCP protocols today (source doc). This is the routing rule that prevents improvisation: the agent should not invent an Access pattern for arbitrary TCP; it routes to private networking (doc 04) instead.

## Boundary case

The source doc also teaches a general routing principle through this domain: when a request only names a trigger without the artifact it acts on, route to the owning surface instead of improvising in this skill (source doc). For infrastructure access this means: SSH plus device client routes to ZTIA; SSH plus no client routes to Browser Rendering or the legacy certificates path; kubectl or database routes to private networking. The [cloudflared TCP access mechanism](https://deepwiki.com/cloudflare/cloudflared/6.3-ssh-rdp-and-tcp-access) underlies all of these (weak source, weight 0.13, corroboration only).
