# 02 - Audit and null standardization

Scope: the `/audit` endpoint's V2 share statistic, the curveball null, the z standardization, dBc, verdicts, idempotency, and the Decision-B multipass mode.

## What an audit measures

Source doc: `POST /api/jev/corpus/audit` takes `{matrix, labels?, nulls?}` and returns `{v2, z, mean, sd, verdict, dbc, shares, E_l, run_id}`. The verdict is one of two strings: "excluded at the resolution of this null" or "not-excluded". The nulls parameter defaults to 100 with a cap of 1000, and the audit is idempotent per input sha256: a repeat call returns the same `run_id` with `cached: true`.

The measurement logic follows the classic Monte Carlo null-testing pattern. In that pattern, a test statistic is computed on the observed data and again on each of N randomized null draws; the observed value is then standardized against the null distribution (SciPy's monte_carlo_test documents exactly this contract, including the option to hand the caller the full Monte Carlo distribution of the statistic, https://docs.scipy.org/doc/scipy/reference/generated/scipy.stats.monte_carlo_test.html, jev weight 0.90). The audit's `z` is that standardized distance, and `mean` and `sd` are the null distribution's moments. Null hypothesis significance testing formalizes the general idea: compare observed data against what a null model would produce, and quantify how surprising the observation is under the null (PMC, https://pmc.ncbi.nlm.nih.gov/articles/PMC5635437/, jev weight 0.74). The z statistic itself has a standard definition: a test statistic whose distribution under the null hypothesis can be approximated by a normal distribution (Wikipedia Z-test, https://en.wikipedia.org/wiki/Z-test, jev weight 0.61). An effect size is a value measuring the strength of a relationship, either as a sample statistic or as a population quantity (Wikipedia, https://en.wikipedia.org/wiki/Effect_size, jev weight 0.56), and the audit's z vs the null is exactly such a strength measure for corpus structure.

## The curveball null

Source doc: the null used is the curveball null, and the Python source of record is `verify_claims.py` (v2_corr, curveball). Curveball is a real published algorithm: it samples graphs with a fixed degree sequence, applying several switches simultaneously ("trades") instead of one at a time, and was introduced as a faster generation of swap-style sampling for bipartite graphs (arXiv 1609.05137, https://arxiv.org/abs/1609.05137v2, jev weight 0.74; the HTML version carries the same abstract, https://arxiv.org/html/1609.05137v2, jev weight 0.66). A random graph model used as a null hypothesis lets researchers deduce the significance of specific properties of a real network, which is why the null must resemble the real network's constraints (ResearchGate, https://www.researchgate.net/publication/308265708_Curveball_a_new_generation_of_sampling_algorithms_for_graphs_with_fixed_degree_sequence, jev weight 0.44 - weak backing).

The family Curveball belongs to is well represented in existing tooling. The R bipartite package's `nullmodel` offers standardized null-model generation for network analysis, with named methods including quasiswap-style shuffles (https://rdrr.io/cran/bipartite/man/nullmodel.html, jev weight 0.73). The nullcat package extends classic binary null models, explicitly naming curveball and swap, to categorical and quantitative data (https://cran.r-project.org/web/packages/nullcat/refman/nullcat.html, jev weight 0.81). A fast MCMC comparison of swap, Curveball, and Rectangle Loop samplers on the same data found Curveball among the efficient uniform samplers of binary matrices with fixed margins (arXiv 1904.03836, https://arxiv.org/pdf/1904.03836, jev weight 0.67). The maximum-entropy random graph model page explains why fixed-constraint nulls matter: distributions that are maximum entropy within a constrained class are maximally non-committal about everything the constraints do not fix (Wikipedia, https://en.wikipedia.org/wiki/Maximum-entropy_random_graph_model, jev weight 0.45 - weak backing).

Why a curveball-style null for a corpus matrix: a coverage matrix is a binary bipartite structure (documents x primitives), and preserving its row and column margins while reassigning individual 1s is exactly what the curveball family does. Meta-validation work on bipartite network projections shows the choice of null model changes which structure reads as significant, so the null must be pinned and named, not swapped silently (Universita di Roma Tor Vergata PDF, https://art.torvergata.it/retrieve/e291c0da-0674-cddb-e053-3a05fe0aa144/s42005-022-00856-9.pdf, jev weight 0.58). A 2026 arXiv paper makes the same point: statistical validation of projected bipartite networks depends critically on the null model adopted for random co-occurrences (arXiv 2607.29242, https://arxiv.org/html/2607.29242v1, jev weight 0.16 - weak backing).

## Reading the outputs

The verdict strings are conservative by design. "Excluded at the resolution of this null" means the observed matrix is distinguishable from what the curveball null produces given the number of null draws requested; "not-excluded" means the null cannot be ruled out at that resolution. Because resolution depends on `nulls`, a marginal result at 100 nulls may resolve at 1000. The z and the null moments are returned alongside the verdict so a caller can compute its own confidence rather than trusting a single boolean.

Two dBc numbers exist and must not be confused. The audit's `dbc` field is an L2 share-spectrum distance to the null-vacuum mean, negative when close, and uncorrelated with z at cycle scale. The round-gate statistic is a different quantity, `level_dbc = 20*log10(|z|)`, also returned by audit-derived state (source doc; see doc 04). Source doc: "do not gate on" the audit's dbc field for round decisions.

## Decision-B multipass

Source doc: added 2026-10-03 (etag adae39aa), the audit accepts `{passes: [matrix x 2..8], labels?, nulls?}` and audits each pass through the same computeAudit path, returning `{multipass, n_passes, passes: [{v2, z, dbc, verdict, run_id}], dbc_mean, dbc_min, dbc_max, inter_pass_offset_dbc}`. The aggregate values are response-only; the passes themselves are recorded and remain idempotent. The pass spread is called the elastic-vs-plastic band: a realized edit effect whose per-pass signs are consistent and whose magnitude exceeds `inter_pass_offset_dbc` is treated as plastic, while anything inside the band or with mixed signs is elastic-by-uncertainty (source doc; see doc 08 for how the gate consumes this).

The multipass design is a hedge against measurement noise in the instrument itself: instead of one audit per state, K audits of the same state bound the run-to-run spread, and that spread becomes the threshold any claimed effect must clear. This is the same reasoning Monte Carlo testing tools encourage when they hand back the full null distribution rather than only a p-value (SciPy, https://docs.scipy.org/doc/scipy/reference/generated/scipy.stats.monte_carlo_test.html, jev weight 0.90).

## Operational notes

Everything except `/health` requires the jev operator bearer; missing or wrong credentials return 401 UNAUTHORIZED (source doc). Send a User-Agent header on every call or Cloudflare rejects with error 1010 (source doc). Nulls above 1000 are capped, so requesting more resolution requires multipass rather than one giant draw count.
